02

Anatomy of an edit

Why every change is undoable: the path a single canvas drag takes.

1

Grab

MoveTool hit-tests, takes a full _snapshot() of every selected shape (position, rotation, geometry, parent).

2

Drag live

Motion applies the delta straight to global_position; SnapManager.smart_snap() nudges it; guides draw in draw_preview().

3

Release → record

_commit_transform() builds a do / undo closure with the before & after snapshots plus any reparent.

4

Push once

ProjectManager registers it on HistoryManager — one action, one stack. DataRepository now holds the new state.

5

Broadcast

GlobalEvents fires. Layers panel, Inspector and the canvas region all refresh — independently, off the bus.

6

Undo

Ctrl+Z in canvas.gd → HistoryManager.undo() replays the closure. Same path, in reverse.

04

Ground rules

The conventions that keep the wiring predictable.

Mutations go through the model

Every data change routes via DataRepository / ProjectManager so undo/redo stays uniform.

Talk on the bus

Prefer GlobalEvents.emit_safe() over direct emit_signal(). Panels don't call panels.

Nodes by unique name

%UniqueName access, not get_node() path strings.

Tools share one contract

Every tool implements activate(), deactivate(), handle_input(event) -> bool.

Static typing, always

All function signatures are statically typed — inferred-Variant is treated as an error.

Draw via redraw

Canvas rendering is queue_redraw() + _draw(), scoped to dirty regions.

Don't hand-edit .tscn

Scene files change through editor / MCP scene tools. UID files are tracked in git.

New code in script_gdscript/

scripts/ and Scene/ are legacy. 100% GDScript — no C#, no .NET.
