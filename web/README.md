# Vectopen website

Static site for Vectopen. No build step — plain HTML, CSS and vanilla JS.
Fonts come from Google Fonts; the blog renders Markdown with `marked` from a
CDN. Everything else ships in this folder.

```
web/
├── index.html               landing page
├── assets/
│   ├── site.css             shared shell (tokens, nav, footer, prose)
│   ├── site.js              theme toggle + i18n engine
│   ├── i18n.js              translation dictionary  ← add languages here
│   └── blog.js              static blog engine (front-matter + markdown)
├── blog/
│   ├── index.html           the blog (post list)
│   ├── post.html            single post  (?p=<slug>)
│   ├── posts.json           GENERATED index — do not edit by hand
│   ├── build-manifest.mjs   regenerates posts.json from the .md front-matter
│   └── posts/<slug>.md      posts (Markdown + YAML front-matter)
├── admin/
│   ├── index.html           Decap CMS
│   └── config.yml           CMS collection config
└── logo.svg / logo.png      the mark, as raw assets
```

`posts.json` is regenerated by `.github/workflows/blog-manifest.yml` on every
push that touches `web/blog/posts/` — GitHub Pages can't list a directory, so
the site reads that index. Run it yourself with `node web/blog/build-manifest.mjs`.

## Preview locally

```sh
cd web && python -m http.server 8080   # http://localhost:8080
```

(Open it over HTTP, not `file://` — the blog uses `fetch`.)

## Deploy

**GitHub Pages** → Settings → Pages → *Deploy from a branch* → `main` / `/web`.
Live at `https://malabo1990.github.io/-Vectopen/`. Or any static host.

## Theme

`site.js` cycles **system → light → dark**, stored in `localStorage`, applied as
`data-theme` on `<html>`. A tiny inline script in each page's `<head>` sets it
before first paint to avoid a flash.

## Translations

`assets/i18n.js` holds one dictionary per language. To add one (e.g. German):

1. In `names`, add `de: "Deutsch"`.
2. Copy the whole `en: { … }` block to `de: { … }` and translate the *values* —
   keep every key.

The switcher and `<html lang>` update automatically. Text in the HTML is the
English fallback (`data-i18n="key"` on the element). Blog **posts** are not
auto-translated — add `posts/<slug>.<lang>.md` and `post.html` picks it up for
that language, falling back to `<slug>.md`.

## Writing a blog post

### With the CMS (Decap)

Zero setup, edits on disk:

```sh
npx decap-server            # repo root, leave running
cd web && python -m http.server 8080
# open http://localhost:8080/admin/  →  Login (local backend)
```

New post → fill Title / Date / Summary / Tags / Body → Save. It writes
`web/blog/posts/<slug>.md` with front-matter. Commit it with git; the
GitHub Action refreshes `posts.json`.

To edit from anywhere at `https://<site>/admin/` you need a GitHub OAuth app
plus an OAuth proxy (Decap can't do the handshake from a static page). The
common free options: deploy Decap's `netlify-cms-oauth-provider` /
`decap-proxy` on Cloudflare Workers or Deno Deploy, register a GitHub OAuth
app pointing at it, then set `backend.base_url` in `admin/config.yml` and
`local_backend: false`. Full walkthrough: <https://decapcms.org/docs/github-backend/>.

### By hand

1. `web/blog/posts/<slug>.md`, starting with front-matter:

   ```markdown
   ---
   title: "…"
   date: 2026-10-01
   summary: "one or two sentences — shown in the list and the homepage teaser"
   tags: [performance, format]
   draft: false
   ---

   Body. Use `##` for headings — the title above is the page H1, don't repeat it.
   ```
2. `node web/blog/build-manifest.mjs` (or just push — the Action does it).

Set `draft: true` to hide a post while writing it. The homepage shows the
newest three; `blog/` lists them all.

Post Markdown is rendered as-is (no sanitising) — it's authored by the repo
owner, so that's fine. Don't paste untrusted HTML into a post.

**Translations:** add `web/blog/posts/<slug>.<lang>.md` (same front-matter) and
`post.html` serves it when that language is active, falling back to `<slug>.md`.

## Keep in sync

When the version, roadmap or feature set changes: the `v0.1.1` tag and the stat
block in `index.html`, the roadmap keys in `i18n.js` (mirror `ROADMAP.md`), and
the docs cards.
